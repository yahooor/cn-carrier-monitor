# 会话生命周期语义表（Session Lifecycle Semantics）

> 本文记录四家运营商在 cn_carrier_monitor 中的会话载体、有效期（TTL）、失效签名与恢复路径。
> 只收「已实证」结论——每个数值/签名都可追溯到本会话受控观察或协议基线复验；未实测项明确标注 PENDING。
> 常量来源与协议漂移处置见 [协议基线.md](协议基线.md)。

## 1. 四家对照总表

| 运营商 | 通道 | 鉴权载体 | TTL | 失效签名 | 续期 | 重登 / 恢复 |
|---|---|---|---|---|---|---|
| 电信 | v2 短信登录（appgologinsz 族） | token（headerInfos 内）+ 短信码绑定发码会话状态 uid/key/isct | **分钟级一次性**（X201 实证），使用不续期 | `headerInfos.code` 1001 / 2001 / 9999 / X201 / X110 | **无**（密码登录才有长效） | 短信全自动滑块已实现（自动发码 → webhook 提交） |
| 电信 | v1 密码登录（userLoginNormal 族） | token | **长效** | 查询失败自动重登 | ✅ 自动续期 | 有服务密码即全自动，无人工 |
| 联通 | 网页 Cookie（mall 域） | mall Cookie（JUT / _uop_id / u_account） | **数小时 ~ 一天**（实测 3-5 小时后过期） | 响应体 999998 / 999999，或 code 1001 | **无** | 浏览器扫码 / 短信+滑块（**ECS1164 账号级强制**，服务端无法全自动） |
| 移动 | wx.10086.cn 网厅 | **uuid Cookie（72h 刷新令牌）** + **d.sid（30min 访问令牌）** | d.sid **30 分钟固定不滑动**；uuid **72 小时** | uniApi 返回 HTML 而非密文；302 到登录页 | d.sid 可自愈重签；**uuid 无任何端点续期 ⇒ 每 72h 必须重新登录** | Edge 收割 Cookie → `inject_token`（见 §7） |
| 广电 | 浏览器会话导入 + 请求重放 | 浏览器登录会话（cURL 整体导入） | **未系统测定**（用户反馈数天，README 按「约 3 天」提示） | HTTP 401/403（WAF 拦截）、响应含「请登录/未登录/登录失效/notlogin」或 status 701 | **无** | Edge 登录 → Copy as cURL → 重新配置（见 §7.5）；阿里云 WAF 使服务端登录不可行 |

## 2. 电信：一次性 token 与发码会话绑定

- **载体**：v2 短信链路签发的 token 位于响应 `headerInfos` 内；v1/v2 双接口族密钥体系不同，token 跨族不通用（协议基线 §1）。
- **验证码不是自由凭据**：短信码提交时必须携带发码会话状态（uid/key/isct）。集成发码后保存该状态、提交时恢复（`import_sms_state`），验证码因此绑定到发码会话——换会话提交即失效。
- **TTL（实证）**：X201 = token 过期。token 为**分钟级一次性**，查询使用**不会**延长有效期。
- **失效签名全集**（`headerInfos.code`）：`1001`、`2001`、`9999`、`X201`、`X110`。集成命中后归类 `auth_expired`，触发自动发码（5 分钟冷却）而非盲目重试。
- **续期**：无。短信 token 到期唯一出路是重登。密码登录（v1 族）token 长效且失效后可凭服务密码自动重登——这是「电信无感方案」选服务密码的原因（协议基线 §4）。
- **重登**：短信全自动滑块已实现（缺口定位误差 ≤4px，实测 N≥6 次成功），即自动发码 → 转发器送码 → 自动提交全链路无人工。

## 3. 联通：mall Cookie 的短周期现实

- **载体**：mall 域 Cookie 三件：`JUT`、`_uop_id`、`u_account`。
- **TTL（实测）**：3-5 小时后过期（数量级：数小时 ~ 一天）。
- **失效签名**：响应体 `999998` / `999999`，或 `code 1001`。集成命中后归类 `auth_expired`。
- **续期**：无——网页 Cookie 模式没有任何保活端点，到期即重登。
- **重登约束**：`ECS1164` 是**账号级强制**风控（H5 直发短信被拒，HA 实测与社区一致），短信重登必须在浏览器内走**扫码 / 短信+滑块**，服务端无法全自动。服务密码模式（App 协议 `onLine` 续期，`desmobile` 归属校验）不受此限。

## 4. 移动：uuid / d.sid 双令牌与自愈链路

wx.10086.cn 网厅的会话是**双层令牌**：

| 令牌 | 角色 | TTL |
|---|---|---|
| `uuid` Cookie | 72h 刷新令牌 | **72 小时** |
| `d.sid` | 30min 访问令牌 | **30 分钟，固定不滑动**（实测 30-40 分钟网页会话 TTL 与此一致） |

- **自愈（Cookie 消融矩阵实证）**：携带**有效 uuid** 请求任意认证 GET（如 `GET /website/spa/main/newHome`），服务端**自动重签 d.sid**：

  | 提交给认证 GET 的 Cookie | 服务端行为 |
  |---|---|
  | 仅有效 uuid（无 d.sid） | **200 + 下发新 d.sid** |
  | 伪 uuid（伪造值） | **强制删除**（会话拒绝） |

  集成把响应的 Set-Cookie 合并回会话串（`mobile.py::_merge_cookies`），保住重签成果——不回收则自愈成果丢失。
- **uuid 的硬边界**：6 个业务端点（余额 / 余量 / 归属地 / 积分等，2026-10-31 实测集）**均不续期 uuid** ⇒ **每 72 小时必须重新登录一次**，无法用任何请求保活绕过。
- **uniApi 三件套头**（`/website/uniApi/*` 必需，反编译裁决可复现，见协议基线 §五）：
  - `csrf-token`：页面内联 `window.user.csrf`，每次加载页面轮换（集成拉 newHome 页提取）；
  - `e76ccba5165fa9b4966ad82a0088e520`：每请求生成的指纹头，算法已移植（`mobile.py::_gen_fingerprint`），无硬件绑定；
  - `Lrsbhbg8`：bundle 硬编码常量 `ZS93dUFVa2kzaEpQSjM0SG55MUFDdz09`。
- **失效签名**：uniApi 返回 **HTML 而非 AES 密文**，或 **302 到登录页**。集成据此判 `auth_expired`。

## 5. 广电：会话导入 + 重放

- **无纯 HTTP 登录方案**：官网在阿里云 WAF 后（实测 403 + acw_sc__v2），短信登录无法服务端复现，会话导入是唯一路线（协议基线 §1）。
- **载体**：浏览器登录会话，以「Copy as cURL」整体导入（URL + Cookie，可选 body），集成按原请求重放。
- **TTL**：**未系统测定**；用户反馈数天（README 按「约 3 天」提示重新导入）。
- **失效签名**（实现判定，`broadnet.py`）：HTTP 401/403、外层 status `701`、或响应体含「请登录 / 未登录 / 重新登录 / 登录失效 / notlogin / nologin」→ `auth_expired` → reauth。
- **运维注意**：WAF 在前，重放请求勿高频（限频预算 ≥30 分钟）。

## 7. 运营者操作手册（会话过期恢复）

### 7.1 通用流程（Cookie 型通道：联通 mall / 移动 / 广电）

1. **开 Edge 窗口**：建议用独立 profile（或 InPrivate），避免与日常浏览 Cookie 混淆。
2. **登录**对应运营商门户（各家入口见下）。
3. **收割**会话（各家方式见下）。
4. **注入 HA**：开发者工具 → 动作 → `cn_carrier_monitor.inject_token`，填 `phone` + `cookies`（`token` / `province_code` / `city_code` 按需）。注入后条目自动 reload。浏览器伴侣脚本的 `push_cookies` 通道最终也落到条目同一 cookies 字段。

### 7.2 电信

- **短信模式（自动化，通常无需人工）**：`auth_expired` → 集成自动发码（冷却 5 分钟）→ 持续通知 → 手机转发器（smsForward / iOS 快捷指令）POST `/api/webhook/cn_carrier_monitor_sms`，JSON：`{"phone": "号码", "code": "验证码"}`（条目配置了 `webhook_secret` 时另带同值 `X-Secret` 头）→ 自动完成重登并回写 token。
- **密码模式**：全自动——token 失效自动用服务密码重登，无人工步骤。
- **手动兜底**：转发器不可用时，在集成卡片的「重新认证」里输入收到的验证码（验证码绑定发码会话，必须用集成发起的发码）。

### 7.3 联通

- **服务密码模式**：自动（`onLine` 续期 + 失效重登），无需人工。
- **mall Cookie 模式**：Edge 窗口 → 登录联通网页版 → DevTools（F12）→ Application/Network 收割 Cookie（确认含 `JUT` / `_uop_id` / `u_account`）→ `inject_token` {`phone`, `cookies`}。
- **短信重登只能在浏览器内完成**（ECS1164 账号级强制：扫码 / 短信+滑块）；实测 mall Cookie 3-5 小时过期，此模式需要较高的手工频率，优先用服务密码。

### 7.4 移动（wx.10086.cn）

- **每 72 小时一次的固定动作**：Edge 窗口 → 登录 `wx.10086.cn` → DevTools → Network → 任意请求 → 复制 `Cookie` 请求头 → `inject_token` {`phone`, `cookies`}。
- **两次重登之间全部自动**：只要 uuid 有效，d.sid 到期由自愈链路自动重签（集成请求 newHome 页时顺带触发，Set-Cookie 自动回收合并），无需人工。
- **触发信号**：事件日志 `cn_carrier_monitor_events.jsonl` 中 `auth_expired` 连续出现 = uuid 已过期（自愈也救不了），执行本流程。
- 收割到的 Cookie 只要 uuid 有效即可（消融矩阵：仅 uuid → 200 + 新 d.sid）。

### 7.5 广电

1. Edge 窗口 → 登录 `www.10099.com.cn`（短信验证码）。
2. 进入「个人中心 / 号码余量」页面，F12 → Network，找到包含 `qryUserRes` 的请求。
3. 右键 → Copy → **Copy as cURL**，整段粘贴到集成 reauth 配置框（或拆成 `cookies` / `request_url` / `request_body` 用 `inject_token` 注入）。
4. 用户反馈会话数天失效（按约 3 天预期）；届时集成发起 reauth，重复上述步骤。WAF 在前，请勿高频重放。

### 7.6 恢复后自检

1. 调用 `cn_carrier_monitor.refresh`（或等下一轮询周期，默认间隔见 README 限频预算表）。
2. 事件日志：`update_success` 恢复、`auth_expired` 不再新增。
3. 实体恢复可用，`login_expired` / `circuit_open` 标记消失。
