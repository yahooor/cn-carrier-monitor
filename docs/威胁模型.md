# 威胁模型（Threat Model）

> 范围：cn_carrier_monitor（Home Assistant 自定义集成）。分析对象是**集成自身引入的资产与攻击面**；HA 核心、宿主机操作系统、家庭路由器是既有信任边界，不在本文展开（仅在与集成资产交互处提及）。
> 方法：STRIDE 简化——按攻击面映射威胁类别，不逐实体展开。
> 缓解措施均引用实际实现（文件与参数可复核）；残余风险按 P1/P2 分级。

## 1. 信任边界与数据流

```
手机转发器(smsForward/iOS快捷指令) ──POST /api/webhook/cn_carrier_monitor_sms──▶ ┌─────────────┐
Edge 浏览器(人工收割) ──inject_token / push_cookies──▶ │  HA 主机     │ ──TLS──▶ 运营商 API
手机短信(验证码) ──────────────────────────────────▶ │  集成进程    │
                                                     │  .storage   │ ──▶ events.jsonl（HA 配置目录，随 HA 备份外发）
                                                     └─────────────┘
```

| 边界 | 说明 |
|---|---|
| LAN → HA webhook | 局域网内任意主机可达 webhook（缺省无鉴权，见 A2） |
| HA → 运营商 API | 出站 TLS；DNS 查询发往公共 DNS（223.5.5.5 / 119.29.29.29，net.py），属出站第三方依赖 |
| HA 配置目录 → 备份介质 | `.storage` 凭据与 `events.jsonl` 随 HA 备份整体外发，备份介质即资产外延 |

## 2. 资产清单

| 资产 | 存储位置 | 形态 | 敏感度 |
|---|---|---|---|
| 服务密码 | entry data → `.storage/core.config_entries` | **明文** | 高——可登录运营商网厅，查询详单、办理业务 |
| token / cookie（电信 token、联通 token_online 与 mall Cookie、移动 SSO Cookie、广电会话） | 同上 | **明文** | 高——等效于已登录会话 |
| uuid 刷新令牌（移动，随 cookies 字段存储） | 同上 | **明文** | 高——72 小时内可凭它重签任意 d.sid（消融矩阵实证，见 [会话生命周期语义表.md](会话生命周期语义表.md) §4） |
| events.jsonl | HA 配置目录（`cn_carrier_monitor_events.jsonl`） | JSONL，**手机号明文** + 成功/失败时序元数据 | 中——个人信息 + 使用模式画像（更新时间规律） |

## 3. 攻击面 × STRIDE（简化）

| # | 攻击面 | 威胁（STRIDE） | 场景 | 现有缓解 | 残余 |
|---|---|---|---|---|---|
| A1 | HA 主机 compromise | I / T / E | 攻击者获得本机文件读权限：`.storage` 中凭据**明文可读 → 四家凭据全失**（服务密码 + token/cookie + uuid 刷新令牌一次泄露） | 主机访问控制（用户责任，README「威胁模型与凭据」已明示）；定期换服务密码（运营商侧重置路径：电信发 `MMBZ#证件后6位` 至 10001，联通 App/10010，移动发 `CZMM#证件后6位` 至 10086） | 明文存储本身（R1）；备份介质同步失守 |
| A2 | webhook `cn_carrier_monitor_sms` | S / D | **缺省局域网内无鉴权**：LAN 攻击者可 POST 任意验证码——抢占/耗尽验证码窗口、干扰重登、反复触发发码 | 可选 `webhook_secret`（条目 options/data 配置后，请求须带同值 `X-Secret` 头或 body `secret` 字段，否则 403，webhook.py）；发码有 5 分钟冷却；连续失败有熔断兜底（A4） | 缺省不启用（R 项见 §5）；错误响应区分 `no_matching_account`(404) / `bad_secret`(403)，未设 secret 时可探测条目存在性 |
| A3 | 事件日志信息泄露 | I | `events.jsonl` 手机号明文 + 更新成功/失败时间序列 → 可推测在网规律；文件随 HA 备份外发 | 轮转已做（≥1MB 轮转 `.jsonl.1`，只保留一代，event_log.py）；文件位于 HA 配置目录，受宿主文件系统权限约束；诊断下载已脱敏（diagnostics.py：密码/token/cookie/openid/URL 抹除、手机号 3+4 掩码） | **手机号明文 + 时序元数据本身未脱敏**（R2） |
| A4 | 运营商风控 | S / D | 高频轮询被识别为非官方客户端 → 滑块、锁定、封号（对**用户运营商账号**的拒绝服务） | 限频预算表（默认 60 分钟、下限 5 分钟，coordinator 强制 `max(interval,5)`）；**连续失败 ≥5 次熔断 15 分钟**（coordinator.py `FAILURE_THRESHOLD=5` / `CIRCUIT_COOLDOWN=900`），期间返回最后一次数据不重试；发码自带 5 分钟冷却 | 无（预算表已在 README 声明为使用约束） |

**Repudiation（不可否认性）补充**：失败四分类日志（`auth_expired` / `protocol_drift` / `network` / `internal`，event_log.py）为每次更新留最小审计痕迹，事后可区分「运营商侧失效 / 网络故障 / 集成内部错误」，部分缓解抵赖类争议。日志无签名，本机攻击者可篡改（归入 A1 的本机威胁，不单列）。

## 4. 已有缓解清单（实现索引）

| 缓解 | 实现 | 说明 |
|---|---|---|
| parse_safe | `api/base.py::parse_safe` | 解析器深层 `.get` 链崩溃统一转 `ParseAnomalyError`（归 `protocol_drift`）——运营商字段类型随省份/套餐漂移（fuzz 实证），畸形响应不让更新裸崩、不进失败风暴 |
| TLS / 网络层 | `net.py::build_connector` | TLS 校验默认开启；仅对 legacy TLS 站点（移动 wx.10086.cn 要求 SECLEVEL=1 + 允许重协商）放宽 cipher 套件；强制 IPv4 + 公共 DNS（223.5.5.5 / 119.29.29.29），防 HAOS coredns 对运营商域名解析不稳放大为失败风暴 |
| webhook_secret | `webhook.py`（`X-Secret` 头 / body `secret`） | 条目配置后不携带同值即 403；跨网使用时必须启用（README 已明示） |
| 熔断器 | `coordinator.py`（`FAILURE_THRESHOLD=5`、`CIRCUIT_COOLDOWN=900.0`） | 连续 ≥5 次失败熔断 15 分钟，保护运营商风控额度；期间实体显示最后数据并打 `circuit_open` 标记 |
| 事件轮转 | `event_log.py`（`MAX_BYTES=1_000_000`） | 超 1MB 轮转为 `.jsonl.1` 只留一代；追加写失败仅降级 debug，绝不影响更新流程 |
| 会话隔离 | `coordinator.py`（每条目独立 `aiohttp.ClientSession`） | 每账号独立 CookieJar，防多账号 Cookie 串号 |
| 诊断脱敏 | `diagnostics.py`（`SENSITIVE_KEYS` + `_mask_phone`） | 诊断下载抹去密码/token/cookie/openid/请求 URL/body，手机号 `3****4` 掩码 |
| 重定向关闭 | `api/base.py::_request`（`allow_redirects=False`） | 不自动跟随 302（移动 SSO 跳转显式处理），防止凭据被带到非预期域 |
| 凭据回写 | `coordinator.py::_async_persist_credentials` | 服务端滑动续期成果（联通 token_online、移动 Set-Cookie 等）写回条目，重启不丢登录态，也缩短「半新半旧 Cookie」窗口 |
| 载荷校验 | `webhook.py`（voluptuous schema） | webhook 请求体不符合 schema 直接 400，畸形输入不进重登链路 |

## 5. 残余风险与建议

### P1

**R1 凭据加密存储**
entry data / `.storage` 全部明文（服务密码、token/cookie、uuid 刷新令牌）。主机被攻破即凭据全失（A1），唯一硬控制是主机访问控制本身。
建议：跟进 HA 凭据存储机制演进，若 HA 提供加密存储 API 则迁移；短期补偿控制——HA 主机访问最小化、HA 备份加密存放、服务密码定期轮换（重置路径见 A1 行）。

**R2 events.jsonl 脱敏**
手机号明文 + 更新时序元数据落盘，且随 HA 备份外发（A3）。文件权限与轮转已做，但内容本身未脱敏。
建议：`emit` 前对 `phone` 做掩码（可复用 `diagnostics.py::_mask_phone` 的 3+4 形态），保留排障可用性；如担心掩码影响对账，提供配置开关而非默认明文。

### P2

**R3 brands 合并后的供应链信任**
合并 `home-assistant/brands` 后，集成进入 HACS 公开发现面，信任根从「手动安装者自审源码」转为「发布链」（GitHub 仓库 → CI → release → HACS 分发），需保证发布链不被投毒、仓库不被仿冒。
有利现状：`manifest.json` requirements 为空——**零第三方运行时依赖**，无依赖投毒面；CI 已有 ruff / pytest / hassfest / HACS 校验门禁。
建议：main 分支保护 + 仅以 tag 触发 release；release 工作流内 actions 固定版本；README 明示唯一官方仓库地址，防同名仿冒。
