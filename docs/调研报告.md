# 调研报告：四运营商话费查询方案（2026-10）

本报告汇总了 cn-carrier-monitor 统一集成的设计依据。所有方案均来自对本地 research/ 目录中开源项目的源码级分析与在线验证。

## 一、各运营商可用方案与选型

### 1. 中国电信 ✅ 服务密码登录（成熟）

**来源**：`ChinaTelecomMonitor/telecom_class.py`、`ha_china_comm/CT/api.py`（两者同源）

- **登录**：`POST https://appgologin.189.cn:9031/login/client/userLoginNormal`
  - 手机号/密码做凯撒 +2 偏移（`trans_number`）
  - `loginAuthCipherAsymmertric` = RSA-PKCS1v15(`iPhone 14 15.4.0{dev12}{phone}{ts}{password}0$$$0.`)，公钥 1024 位（SPKI base64，已内置）
  - `headerInfos`: code=userLoginNormal, clientType=`#12.2.0#channel50#iPhone 14 Pro#`, timestamp=`YYYYMMDDHHMM00`（分钟精度）, shopId=20002, source=110003, sourcePassword=Sid98s
- **响应**：`responseData.resultCode == "0000"` → `responseData.data.loginSuccessResult` 内含 token、provinceCode、cityCode
- **错误码**：3005 需图形码 / 3006 设备未信任 / 3007 过频 / 3008、3009 锁定
- **查询**：`POST https://appfuwu.189.cn:9021/query/qryImportantData`（携带 token）→ flowInfo（totalAmount/commonFlow/specialAmount，KB）、voiceInfo、smsInfo、balanceInfo（balance/arrear 元，phoneBillRegion.subTitleHh 本月消费）、integralInfo
- **TLS 坑**：需 `SECLEVEL=1` cipher 上下文，失败时降级 verify=False
- **token 失效**：查询失败自动重新登录（有密码在握，可全自动恢复）

**选型**：✅ 采用。短信登录（e.189.cn Web AES 动态密钥链路）复杂且脆弱，不采用。

### 2. 中国联通 ✅ 服务密码（App 协议）+ openid 兜底

**来源 A（密码，主选）**：`QLScriptPublic/daily/chinaUnicom.py`
- `POST https://m.client.10010.com/mobileService/login.htm`
- 表单：`mobile`=RSA_PKCS1v15(手机号+6位随机数字)、`password`=RSA(密码+6位随机数字)、`reqtime`、`version=android@11.0900`、`appId`（固定模板 159 位，含 7 个随机位）
- 公钥 2048 位（已内置）；响应 code∈(0,0000) → `token_online` + 会话 Cookie
- **续期**：`POST .../mobileService/onLine.htm`（token_online+appId）→ 新 Cookie（`liuliang-buddy/unicom_app_client.dart` 验证：code==0 且 `desmobile` 返回本机号码；续期失败/查询返回 999998、999999 → 会话失效）

**来源 B（openid，兜底）**：`unicom-mini-ha`、`ha_unicom_bill`、`ha_china_comm/CU`
- `mina.10010.com/wxapplet/weixinNew/getToken`（openid 字段 = RSA-2048(openid)）→ token → 所有接口 openid = RSA(token+openid)
- sspbigball 概览、queryGoodsList 完整号码、sspbalcbroadcast 余额
- 微厅链路：getTicket → serviceEntrance 302 链收集 microHallUser Cookie → queryOcsPackageFlowLeftContentRevisedInJune 余量明细（流量 MB、语音、短信、通用/定向分项）

**选型**：✅ 双模式。**短信登录不可行**——App 短信端点（sendRadomNum.htm）无公开稳定参数，社区脚本全线下架。

### 3. 中国移动 ✅ 短信验证码（纯 HTTP）+ 服务密码 + Cookie

**来源 A（登录链路）**：`cmcc-unsub/pure_login.py`（自述"完整复刻 login.10086.cn 短信随机码登录链路"）
1. `GET https://login.10086.cn/login.html?channelID=12003&backUrl=...`（建会话）
2. `POST /loadToken.action` → 风控 token（作为 `Xa-before` 头）
3. `POST /sendRandomCodeAction.action` → 发短信（参数为社区逆向， best-effort）
4. `POST /login.htm`：`account`=RSA2048(手机号)、`password`/`smsPwd`=RSA2048(验证码)、`pwdType=02`（短信）/`01`（服务密码）、`deviceId`（按号码确定性派生 32hex_32hex，规避同设备多号风控）、`channelID=12003`、`timestamp`
5. `result==0` → `assertAcceptURL?backUrl=&artifact=&type=` → 跟随落 SSO Cookie（cmccssotoken / is_login）
6. 错误码：6001 验证码错误 / 3012 图形码 / 8009、8012、8002 锁定/密码错

**来源 B（查询 + 解密）**：`ChinaMobileMonitor/chinamobile.py`、`liuliang-buddy/page_probe.dart`
- `https://wx.10086.cn/website/serviceMargin/getMainPlan`（代码中硬编码路径，已实测可达）→ `object.resultData.curPlanName`
- `getNewMarginInfo` → 流量/语音/短信余量：planRemainFlowInfo.planRemain / directionalFlowInfo / otherRemian / totalInfo（usedNum/sumNum/remainNum/unit，01=分钟 02=条 03=MB 04=GB）
- `fareBalance` → `data.realFeeQryRsp.curFeeTotal` 余额
- **响应为 AES-128-CBC hex**：key=`1234123412ABCDEF`，iv=`ABCDEF1234123412`（两个项目独立验证一致）
- 查询时携带 SSO Cookie（.10086.cn 域通吃）

**来源 C（备查）**：`cmcc-auto-checkin/cmcc_fee.py`（touch.10086.cn 充值页通道，需 App 抓 jsessionid-cmcc，不采用）；`china-mobile-10086-ha`（HAOS 浏览器插件 + 文件命令桥，过重，不采用）

**实测验证**（本次调研中 curl 实测）：login.html=200、loadToken.action 返回 `{"rspType":"0","rspCode":"3001"}`（需参数）、sendRandomCodeAction.action 存在（无参时 upstream reset）

**选型**：✅ 短信链路为主，密码/Cookie 兜底。发送端点参数不完全确定，失败时配置流给出明确错误并引导换方式。

### 4. 中国广电 ⚠️ 会话导入（无纯 HTTP 方案）

**结论：社区无任何现成广电集成**（GitHub/HACS/hassbian 检索确认），且官网在阿里云 WAF 后（实测 www/wx.10099.com.cn 均 403 + acw_sc__v2/接口反爬 JS），短信登录无法服务端复现。

**来源**：`liuliang-buddy`（四运营商 App，广电链路最完整）
- 登录页：`https://www.10099.com.cn/login.html`（短信验证码）
- 查询页：`https://www.10099.com.cn/personal-center-number-order.html`
- 会话：sessionStorage 的 `broadnetUserPhoneInfo` + `broadnetUserSessionId`（用户反馈约 3 天失效）
- 查询接口：URL 含 `qryUserRes`（www 或 wx.10099.com.cn），响应由站点 JS dataFilter 解码
- **响应结构（parseBroadnetH5 已验证）**：`{status:"000000", data:{respCode:"000000", intfResultBean:{userResList:[...]}}}`；`busiType=5` 流量（balance=剩余 KB，highFee=总量 KB）、`busiType=1` 语音、名称含"短信"→短信；`discntName` 名称；支持"不限量"字样

**选型**：✅ 会话导入 + 请求重放。用户浏览器登录后「Copy as cURL」一键粘贴（集成内置 cURL 解析器），失效自动 reauth。与 liuliang-buddy 的实现哲学一致，但不依赖其 App。

## 二、HA 集成架构参考结论

对 `ha_china_comm`（电信+联通双运营商、config flow、多账号）、`ChinaTelecomMonitor-Homeassistant-Integration`、`ha_unicom_bill`、`unicom-mini-ha` 的分析：

| 维度 | 社区现状 | 本集成 |
|---|---|---|
| 运营商覆盖 | 电信+联通（无移动/广电纯 HTTP 方案） | 四家 |
| 多账号 | ha_china_comm 支持多条目 | ✅ 每账号一条目 + per-entry CookieJar 防串号 |
| 登录交互 | 电信密码表单；联通粘贴 openid | ✅ 分步 flow：短信发码/输码、密码、cURL 导入 |
| 失效处理 | 多数仅报错停更 | ✅ CarrierAuthError → ConfigEntryAuthFailed → 自动 reauth |
| 实体设计 | sensor 若干（ha_unicom_bill 634 行最全） | ✅ 统一归一化数据模型 + translation_key 双语 |
| 依赖 | 多数要求 pycryptodome | ✅ 仅用 HA 自带 `cryptography`，manifest requirements 为空 |

## 三、用户实际号码分布（影响设计优先级）

来自用户提供的《目前个人正在使用中的互联网电话卡.xlsx》：

- 电信 ×4（山东济宁 1 + 湖南张家界 3，含副卡）→ 电信服务密码方案为最高优先级，且需支持跨省
- 联通 ×3（张家界 2 + 北京 1，其一在销卡流程）→ 双模式覆盖
- 移动 ×1（张家界 8 元保号）→ 短信登录
- 阿里小号 ×2、giffgaff ×1 → 无法接入，README 已注明
